# Деплой litmob.ru на Timeweb Cloud (Apps, Dockerfile)

Схема: **приложение** (Timeweb Apps, сборка из `Dockerfile`) + **PostgreSQL**
(управляемая база Timeweb) + **S3-бакет** Timeweb для обложек и аудио.
Диск контейнера стирается при каждом деплое, поэтому файлы — только в S3.

## 1. База данных

Timeweb Cloud → Базы данных → Создать → **PostgreSQL 17**, регион тот же, что у приложения
(минимальная конфигурация подойдёт). Создайте базу `litmob` и пользователя.
Скопируйте строку подключения — это `DATABASE_URL`:

```
postgres://USER:PASSWORD@HOST:5432/litmob?sslmode=require
```

Если приложение и база в одной приватной сети — берите приватный адрес хоста.

## 2. S3-бакет

Хранилище S3 → Создать бакет, тип **публичный**. Из карточки бакета:

| Переменная | Значение |
|---|---|
| `S3_BUCKET` | имя бакета |
| `S3_ENDPOINT` | `https://s3.twcstorage.ru` |
| `S3_REGION` | `ru-1` |
| `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` | ключи доступа |
| `S3_PUBLIC_URL` | `https://s3.twcstorage.ru/<имя-бакета>` |

## 3. Приложение

Apps → Создать → **Dockerfile** → репозиторий `dvasincom-sketch/litmob`, ветка `main`
(авто-деплой по push можно оставить включённым).

- Порт: **3000**. Health-check уже в образе: `/api/health/`.
- Конфигурация: **не меньше 4 ГБ RAM** — `next build` на 2 ГБ падает по памяти.
- Переменные окружения:

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | из шага 1 |
| `PAYLOAD_SECRET` | `openssl rand -hex 32` (сохраните, менять потом нельзя — разлогинит всех) |
| `NEXT_PUBLIC_SITE_URL` | `https://litmob.ru` |
| `S3_*` | из шага 2 |
| `SEED_ON_START` | `1` — **только на первый деплой** |
| `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` | почта и **новый** пароль админа |
| `CONTENT_ON_START` | `1` — заливает тексты из `content/` в пустые поля страниц (правки из админки не трогает), можно не выключать |
| `SMTP_*`, `EMAIL_FROM_*` | по желанию (письма сброса пароля) |

При старте контейнер выполняет `npm run migrate` → (если `SEED_ON_START=1`) `npm run seed` → `npm run start`.

## 4. Первый деплой и уборка

1. Запустите деплой. В логе должно быть:
   `Готово: семейств 7, сюжетов 36, уточнений 25, …` и `✓ Ready`.
2. Проверьте технический адрес Timeweb: `/api/health/`, главную, `/admin/` (вход админом).
3. **Удалите** `SEED_ON_START`, `SEED_ADMIN_PASSWORD` и передеплойте.
   Сид перезаписывает тексты сюжетов и страниц из `src/seed/structure.ts` —
   при каждом старте он затёр бы правки из админки.

Демо-книги (`npm run seed:demo`) на проде не запускаем.

## 5. Домен

1. В настройках приложения → Домены: добавьте `litmob.ru` и `www.litmob.ru`,
   включите бесплатный SSL (Let's Encrypt).
2. У регистратора домена (DNS):
   - `litmob.ru` → **A**-запись на IP, который покажет Timeweb;
   - `www` → **CNAME** на `litmob.ru` (или та же A-запись).
3. Подождите обновления DNS (обычно до часа), затем выпустите сертификат.

`www.litmob.ru` автоматически отдаёт 301 на `litmob.ru` (`src/proxy.ts`):
вход и CSRF привязаны к одному адресу — `NEXT_PUBLIC_SITE_URL`.
Если сайт открыт по другому адресу (например, технический домен Timeweb),
вход в админку не сработает — это ожидаемо, проверяйте вход на `litmob.ru`
либо временно поставьте этот адрес в `NEXT_PUBLIC_SITE_URL`.

## 6. После запуска

- Яндекс Вебмастер и Google Search Console: добавить сайт, выбрать подтверждение
  мета-тегом и положить код в `YANDEX_VERIFICATION` / `GOOGLE_SITE_VERIFICATION`
  (только значение `content`), передеплоить, указать `https://litmob.ru/sitemap.xml`.
- В карту сайта попадают главная, хабы семейств и литмобы; страница сюжета
  или жанра появляется в ней, когда набирает `minBooksToIndex` книг
  (по умолчанию 5, Админка → Настройки сайта). До этого — `noindex`.

## Обновления

`git push` в `main` → Timeweb пересобирает образ, миграции применяются на старте.
Новая миграция: `npm run migrate:create <имя>` локально, закоммитить файл и запись в `src/migrations/index.ts`.

## Тексты страниц

Статьи и тексты сюжетов/жанров лежат в `content/pages/*.md` и `content/landing/*.md`
(формат и правила — в `src/seed/content.ts` и `docs/content-brief.md`).
С `CONTENT_ON_START=1` они попадают в базу при старте контейнера — только в пустые поля.
Локально: `npm run seed:content` (или `-- --force`, чтобы перезаписать текст из файлов).
